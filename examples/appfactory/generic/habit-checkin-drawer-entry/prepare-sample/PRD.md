# 习惯打卡 App（抽屉录入）

- PRD ID: prd-habit-checkin-drawer-entry-sample-001
- Version: 0.1.0
- Status: draft

## 摘要

把习惯打卡需求整理成基于通用中性交互承载 Flutter 模板的 Android MVP 规格，并保留完成状态分布与打卡记录语义。

## 问题陈述

generic compile 在映射到 open-lite 骨架前，不能把习惯打卡的完成状态分布、打卡记录和时间信息压平成无差别 record。

## 目标用户

- 习惯打卡 应用使用者：需要一个离线可用的习惯打卡工具，用于持续记录并查看完成状态。 关键痛点：自然语言需求容易在 compile 后丢失完成状态和打卡时间语义；希望在统一模板上保留习惯记录文案
- 内部验证人员：需要快速确认 PRD 与 builder-input 是否同时保留领域语义和中性交互承载约束。 关键痛点：需要确认完成状态分布和最近记录是否进入 PRD；不能只验证通用 CRUD 骨架是否存在

## 核心场景

- 查看习惯摘要：用户打开应用后可以看到总记录数和完成状态分布。
- 创建习惯记录：用户可以通过实体变更承载单元创建习惯记录，并立即回到概览或集合浏览入口看到结果。
- 编辑习惯记录：用户可以从结果检查入口进入实体变更承载单元，更新标题、分类、状态和备注。
- 查看习惯详情：用户可以从概览或集合浏览入口进入结果检查入口查看单条习惯记录。
- 按状态查看习惯记录：用户可以在集合浏览承载单元按完成状态切换视图，快速查看最近打卡记录。

## 目标

- 输出覆盖概览、集合浏览、实体变更、结果检查和本地存储的习惯打卡 PRD 与 builder-input。
- 保留完成状态分布、最近记录和打卡信息等核心领域语义，再映射到 flutter-open-lite 中性交互承载骨架。
- 让后续 Builder 能明确收口为习惯打卡 app，而不是停在中性 seed。

## 非目标

- 不引入登录、支付、广告、地图、推送、实时通信。
- 不把远端 API 或自建服务器当作模板基础依赖。
- 不处理上架、签名或复杂商业化配置。

## 功能列表

- 习惯概览承载单元（P0）：提供完成状态分布和最近记录，作为习惯打卡的概览入口。
- 习惯记录集合承载单元（P0）：按时间展示最近习惯记录，支持按完成状态查看，并允许进入结果检查入口。
- 习惯记录变更承载单元（P0）：支持新增或编辑习惯记录，并提供标题、分类、状态和备注输入。
- 本地持久化（P1）：习惯打卡 数据本地持久化，应用重启后仍能恢复。

## 交互承载单元

- 概览承载单元：承载领域摘要观察、导航入口和最近结果回看。
- 集合浏览承载单元：承载领域记录集合浏览、筛选和结果定位。
- 实体变更承载单元：承载实体创建、编辑、校验和保存动作。
- 结果检查承载单元：承载单条记录检查、删除确认和结果回流。

## 用户流程

### 创建习惯记录

- 从概览入口进入新建动作，期望结果：可以看到习惯标题、分类、状态和备注字段
- 填写表单并保存，期望结果：表单校验通过并保存成功
- 返回概览入口查看最新摘要，期望结果：首页摘要和最近记录已刷新

### 编辑习惯记录

- 从集合浏览入口进入结果检查入口，期望结果：能看到单条记录详情与编辑入口
- 进入实体变更入口并修改字段，期望结果：习惯标题、分类、状态与备注可被更新
- 保存后返回结果检查入口，期望结果：详情页显示最新内容

### 查看习惯详情

- 从概览入口进入集合浏览入口，期望结果：能看到完整记录列表
- 点击一条记录进入结果检查入口，期望结果：能看到单条习惯记录的标题、状态、备注和打卡时间

### 按状态查看习惯记录

- 从概览入口进入集合浏览入口，期望结果：能看到筛选入口和完整记录列表
- 切换筛选视图，期望结果：列表立即收敛到对应完成状态的习惯记录

## 数据实体

### 习惯记录

- habit_record_id：string，习惯记录唯一标识
- title：string，习惯标题
- category：string，习惯分类
- status：enum[pending,done]，完成状态
- checked_at：date，打卡时间
- note：string，补充备注

### 习惯概览摘要

- total_count：int，习惯记录总数
- pending_count：int，未完成记录数
- done_count：int，已完成记录数

## 模板约束

- 技术栈：flutter
- Android 必须：是
- 必需能力：navigation、local-storage、theme、summary-card、list、form、detail

## 验收标准

- 习惯摘要完整：概览承载单元必须展示总记录数和完成状态分布。
- 习惯记录集合承载单元可浏览：集合浏览承载单元必须按时间展示最近习惯记录，支持查看完成状态，并允许进入结果检查入口。
- 习惯记录变更承载单元链路完整：用户可以通过实体变更承载单元创建或编辑一条习惯记录并立即看到结果。
- 结果检查入口可达：从概览或集合浏览入口至少存在一条进入结果检查入口的路径。
- 本地持久化可恢复：应用重启后仍能读取本地记录数据。
- 核心承载单元可导航：当前需求声明的概览、集合浏览、实体变更和结果检查承载单元之间路径明确且可达。

## 人工审核点

- 检查习惯打卡语义是否完整进入 PRD：完成状态分布、打卡时间和记录字段不能被通用 record 话术覆盖。
- 确认领域实体能映射到 open-lite 中性交互承载骨架：compile 后必须在复用概览、集合浏览、实体变更和结果检查承载单元的同时保留领域字段。
- 确认首页摘要承接完成状态分布语义：首页摘要必须保留总数与完成状态分布，而不是只有通用计数。
