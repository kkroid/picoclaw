# 人工约束

- 当前体重记录模板默认本地优先，不接入登录、云同步、图表分享和社区能力。
- 模板当前仍复用 open-lite 中性交互承载骨架，但不能牺牲体重、日期、备注与趋势等核心语义。
- 当前阶段仍以稳定 Builder 输入包和多页面 seed 为主，不把远端 API 作为默认前提。
- 需求拆解后二开应优先复用概览、历史集合、实体变更、结果检查四类承载单元，而不是新增第二套平行骨架。
- 当前需求未声明的承载单元不得被 compile 自动补齐。

## 人工备注

- Builder 后续必须把中性 record 骨架收口为体重记录 app，而不是停在 open-lite 默认文案。
- 当前需求只围绕集合浏览和结果检查和本地持久化展开，未声明承载单元和流程不要自动补齐。
