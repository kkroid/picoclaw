# 待办事项 App（无首页无详情）

- PRD ID: prd-todo-lite-no-home-no-detail-sample-001
- Version: 0.1.0
- Status: draft

## 摘要

把待办事项需求整理成基于通用中性交互承载 Flutter 模板的 Android MVP 规格，并保留待办状态分布与任务字段语义。

## 问题陈述

generic compile 在映射到 open-lite 骨架前，不能把待办的状态分布、标题、分类和备注等语义压平成无差别 record。

## 目标用户

- 待办事项 应用使用者：需要一个离线可用的轻量待办工具，用于管理单一任务闭环。 关键痛点：需求常先以自然语言描述，后续容易丢失待办状态语义；希望在统一模板上保留待办领域文案
- 内部验证人员：需要快速确认 PRD 与 builder-input 是否同时保留领域语义和中性交互承载约束。 关键痛点：需要确认待办状态分布是否进入 PRD；不能只验证通用 CRUD 骨架是否存在

## 核心场景

- 创建待办：用户可以通过实体变更承载单元新建待办，并立即回到概览或集合浏览入口看到结果。

## 目标

- 输出覆盖概览、集合浏览、实体变更、结果检查和本地存储的待办事项 PRD 与 builder-input。
- 保留待整理、进行中、已完成等状态语义，再映射到 flutter-open-lite 中性交互承载骨架。
- 让后续 Builder 能明确收口为待办事项 app，而不是停在中性 seed。

## 非目标

- 不引入登录、支付、广告、地图、推送、实时通信。
- 不把远端 API 或自建服务器当作模板基础依赖。
- 不处理上架、签名或复杂商业化配置。

## 功能列表

- 待办集合浏览承载单元（P0）：按时间顺序展示全部待办，支持按状态筛选，并允许进入结果检查入口。
- 待办变更承载单元（P0）：支持新增或编辑待办，并提供标题、分类、状态和备注输入。
- 本地持久化（P1）：待办事项 数据本地持久化，应用重启后仍能恢复。

## 交互承载单元

- 集合浏览承载单元：承载领域记录集合浏览、筛选和结果定位。
- 实体变更承载单元：承载实体创建、编辑、校验和保存动作。

## 用户流程

### 创建待办

- 从集合浏览入口进入新建动作，期望结果：可以看到标题、分类、状态和备注字段
- 填写表单并保存，期望结果：表单校验通过并保存成功
- 返回集合浏览入口查看最新结果，期望结果：集合浏览入口已展示最新记录

## 数据实体

### 待办事项

- task_id：string，待办唯一标识
- title：string，待办标题
- category：string，待办分类
- status：enum[inbox,inProgress,done]，待办状态
- note：string，补充备注

## 模板约束

- 技术栈：flutter
- Android 必须：是
- 必需能力：navigation、local-storage、theme、list、form

## 验收标准

- 待办集合浏览承载单元可浏览：集合浏览承载单元必须展示完整待办、支持按状态筛选，并允许进入结果检查入口。
- 待办变更承载单元链路完整：用户可以通过实体变更承载单元创建或编辑一条待办并立即看到结果。
- 本地持久化可恢复：应用重启后仍能读取本地记录数据。
- 核心承载单元可导航：当前需求声明的集合浏览和实体变更承载单元之间路径明确且可达。

## 人工审核点

- 检查待办领域文案是否完整进入 PRD：待办标题、状态分布和任务字段不能被通用 record 话术覆盖。
- 确认领域实体能映射到 open-lite 中性交互承载骨架：compile 后必须在复用集合浏览和实体变更承载单元的同时保留领域字段。

- 当需求出现复杂多实体关系时，是继续扩展 record 模型，还是拆出新模板（影响：medium）
