# 体重记录 App

- PRD ID: prd-weight-tracker-sample-001
- Version: 0.1.0
- Status: draft

## 摘要

把体重记录需求整理成基于通用中性交互承载 Flutter 模板的 Android MVP 规格，并保留体重、日期、备注和趋势等核心语义。

## 问题陈述

generic compile 在映射到 open-lite 骨架前，不能丢失体重、日期、备注和趋势等核心领域语义，否则最终生成物会退化成只有通用 record 壳子的伪成功样本。

## 目标用户

- 体重记录 应用使用者：需要一个离线可用的个人体重记录工具，用于持续记录并回看变化趋势。 关键痛点：自然语言需求容易在 compile 后丢失体重字段和趋势语义；希望先有稳定骨架，再逐步收口为健康记录产品
- 内部验证人员：需要快速确认 PRD 与 builder-input 是否同时保留领域语义和中性交互承载约束。 关键痛点：需要确认体重、日期、备注和趋势是否进入结构化 PRD；不能再只验证多页面骨架是否存在

## 核心场景

- 查看体重摘要：用户打开应用后可以看到最新体重、记录数量和最近趋势。
- 新增体重记录：用户可以通过实体变更承载单元录入体重、日期和备注，并立即回到概览或历史集合入口看到结果。
- 编辑体重记录：用户可以从结果检查入口进入实体变更承载单元，更新体重、日期和备注。
- 删除体重记录：用户可以删除单条体重记录，并让概览摘要和历史集合同步刷新。
- 查看体重详情：用户可以从概览或历史集合入口进入结果检查入口查看单条体重记录。

## 目标

- 输出覆盖概览、历史集合、实体变更、结果检查和本地存储的体重记录 PRD 与 builder-input。
- 保留体重、日期、备注与趋势等核心领域语义，再映射到 flutter-open-lite 中性交互承载骨架。
- 让后续 Builder 能在不改承载单元绑定的前提下，明确收口为体重记录 app。

## 非目标

- 不引入登录、支付、广告、地图、推送、实时通信。
- 不把远端 API 或自建服务器当作模板基础依赖。
- 不处理上架、签名或复杂商业化配置。

## 功能列表

- 体重概览承载单元（P0）：展示最新体重、记录数量和最近趋势，作为体重记录的概览入口。
- 历史记录集合承载单元（P0）：按日期倒序展示历史体重记录，并允许进入结果检查入口。
- 体重记录变更承载单元（P0）：支持录入体重、日期和备注，并可用于新增或编辑记录。
- 体重记录删除（P0）：支持删除单条体重记录，并让概览摘要和历史集合同步刷新。
- 本地持久化（P1）：体重记录 数据本地持久化，应用重启后仍能恢复。

## 交互承载单元

- 概览承载单元：承载领域摘要观察、导航入口和最近结果回看。
- 集合浏览承载单元：承载领域记录集合浏览、筛选和结果定位。
- 实体变更承载单元：承载实体创建、编辑、校验和保存动作。
- 结果检查承载单元：承载单条记录检查、删除确认和结果回流。

## 用户流程

### 新增体重记录

- 从概览入口进入新建动作，期望结果：可以看到体重、日期和备注字段
- 填写表单并保存，期望结果：表单校验通过并保存成功
- 返回概览入口查看最新摘要，期望结果：首页摘要和最近记录已刷新

### 编辑体重记录

- 从概览或集合浏览入口进入结果检查入口，期望结果：能看到单条记录详情与编辑入口
- 进入实体变更入口并修改字段，期望结果：体重、日期与备注可被更新
- 保存后返回结果检查入口，期望结果：详情页显示最新内容

### 删除体重记录

- 在结果检查入口触发删除动作，期望结果：看到删除确认提示
- 确认删除并返回上一层，期望结果：概览或集合浏览入口不再显示该记录

### 查看体重详情

- 从概览入口进入集合浏览入口，期望结果：能看到完整记录列表
- 点击一条记录进入结果检查入口，期望结果：能看到单条体重记录的体重、日期和备注

## 数据实体

### 体重记录

- record_id：string，记录唯一标识
- weight：number，体重数值
- recorded_at：date，记录日期
- note：string，补充备注

### 体重概览摘要

- latest_weight：number，最近一次记录的体重
- record_count：int，累计记录数量
- trend：string，最近趋势摘要

## 模板约束

- 技术栈：flutter
- Android 必须：是
- 必需能力：navigation、summary-card、list、form、detail、local-storage、theme

## 验收标准

- 体重摘要完整：概览承载单元必须展示最新体重、记录数量和最近趋势摘要。
- 历史记录集合承载单元可浏览：历史集合承载单元必须按日期展示体重记录，并允许进入结果检查入口。
- 体重记录变更承载单元链路完整：用户可以通过实体变更承载单元录入或编辑体重、日期和备注，并立即看到结果。
- 结果检查入口可达：从概览或集合浏览入口至少存在一条进入结果检查入口的路径。
- 删除链路完整：删除体重记录后，概览摘要和历史集合内容必须同步刷新。
- 本地持久化可恢复：应用重启后仍能读取本地记录数据。
- 核心承载单元可导航：概览、历史集合、实体变更和结果检查入口之间路径明确且可达。

## 人工审核点

- 检查体重领域语义是否完整进入 PRD：体重、日期、备注和趋势不能在 compile 阶段被压平成通用 record 话术。
- 确认领域实体能映射到 open-lite 中性交互承载骨架：compile 后必须在复用概览、集合浏览、实体变更、结果检查承载单元的同时保留领域字段。
- 确认首页摘要仍然承接体重趋势语义：首页摘要不能退化为只有通用计数字段的中性概览。
