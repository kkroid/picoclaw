# 收口检查清单

目标：把 Flutter 收口阶段限制在低风险、可回放、可审计的修补范围内。

## 收口前判断

只有满足以下条件，才进入收口：

- 已经有真实功能代码，而不是只有计划或页面壳子。
- 默认 counter demo 已基本移除。
- 首页概览、记一笔、账单列表至少已有主要入口。
- 当前剩余问题主要表现为 analyze、test、build 失败，而不是功能尚未实现。

如果这些条件不满足，就不要把当前阶段称为收口。

## 收口时允许做的事

- 修导入、命名、类型和 Flutter API 兼容性问题。
- 修测试断言与页面真实行为之间的小范围偏差。
- 修构建配置或轻量依赖接线问题。
- 补齐为了 analyze/test/build 通过所必须的最小缺口。

## 收口时禁止做的事

- 借收口名义重做页面结构。
- 换状态管理方案。
- 改本地持久化技术路线。
- 把失败问题扩展成新的大规模功能开发。

## 输出要求

- 说明收口前失败的是哪些检查项。
- 说明本轮修了哪些直接问题。
- 说明收口后通过了哪些检查项。
- 如果仍未通过，要明确卡在 analyze、test、build、环境中的哪一类。
