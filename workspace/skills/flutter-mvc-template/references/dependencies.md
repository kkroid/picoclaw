# 依赖白名单

目标：减少模板漂移，避免 Builder 每次都重新选择技术栈。

推荐默认白名单：

- 路由：原生 `Navigator`，需要声明式路由时才允许 `go_router`。
- 本地存储：`shared_preferences` 仅用于轻配置；业务数据存储在 `hive` 或 `isar` 二选一。
- 日期与金额格式化：`intl`。
- 测试：`flutter_test`，确有 mock 需求时允许 `mocktail`。

记账类工具 App 默认选择：

- 本地持久化默认优先 `hive`，除非 PRD 明确要求复杂查询或模板已经冻结在 `isar`。
- `shared_preferences` 不用于存账单明细，只用于轻量偏好设置。
- 不同时引入 `hive` 和 `isar`。

状态管理策略：

- 如果页面规模较小，优先使用原生 `ChangeNotifier` 或控制器自管理状态。
- 如需额外状态库，只能在模板级冻结一个，不允许同一工程并存多个同类方案。

选择规则：

- 优先沿用模板已有依赖，不为了“更先进”替换成熟方案。
- PRD 未要求离线复杂查询时，不要引入过重数据库层。
- 只要原生能力够用，就不要增加额外包装库。
- 记账类最小实现优先走“单一本地仓储 + 单一本地存储库”闭环，不要先上同步、导入导出或复杂索引。

输出时需要显式说明：

- 这次生成用了哪些白名单依赖。
- 是否复用了模板既有库。
- 是否存在白名单外依赖以及理由。
- 如果是记账类 App，要明确说明账单数据最终落在哪个本地存储方案。
